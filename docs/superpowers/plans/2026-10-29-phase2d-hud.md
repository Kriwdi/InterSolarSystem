# Phase 2d Ship HUD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A hajó állapota (fázis, számláló, alrendszerek, incidensek) a szerverről a hajóban lévő játékosoknak jut el, és egy kliensoldali HUD-panelen jelenik meg.

**Architecture:** Tiszta Java mag a közös kódban: `ShipStatusSnapshot` (a szerver adatai), `ShipStatusPayload` (hálózati csomag és kodek), `ShipStatusSyncPolicy` (kinek mikor küldünk), `ShipHudModel` (a megjelenítendő sorok). A szerveroldali `ShipStatusSync` a tick-kezelőből küld; a kliens `ClientShipStatus` tárolja az utolsó pillanatképet, a `ShipHudElement` rajzol.

**Tech Stack:** Java 25, Minecraft 26.3, Fabric API (`PayloadTypeRegistry`, `ServerPlayNetworking`, `ClientPlayNetworking`, `HudElementRegistry`), JUnit 5.

**Spec:** `docs/superpowers/specs/2026-10-29-phase2d-hud-design.md`

## Global Constraints

- Minecraft 26.3; mod ID `intersolarsystem`; csomag `hu.kriwdi.intersolarsystem` (`ship` modul; kliens kód: `...client`).
- Kliens/szerver szétválasztás: a `src/main` nem hivatkozhat kliens osztályra (`net.minecraft.client.*`, a Fabric kliens API-k). A rajzolás és a tároló a `src/client`-ben van.
- Az állapot szerveroldali; a kliens csak megjelenít. Nincs új mentésformátum.
- Súlyossági küszöbök: `ShipIncidentRules.SAFE_CONDITION` (70) és `ShipFlightRules.MIN_TAKEOFF_CONDITION` (20); villogás az utolsó `300` tickben. A kliens ezeket a konstansokat használja.
- Nincs új lang kulcs: a HUD a meglévő kulcsokat használja (`message.intersolarsystem.ship.countdown.<fázis>`, `ship.intersolarsystem.phase.landed`, `ShipCommands.subsystemKey`/`incidentKey`, `message.intersolarsystem.ship.alert_line`).
- **A játék futása közben tilos a Gradle build** (összeomlasztja a futó klienst). Build előtt `pgrep -f '[K]notClient'`, és ha fut, kérdezd meg a felhasználót.
- API-pontosság: az alább **jarból ellenőrzött** szignatúrákat használd; ami nincs ellenőrizve, annak lépése jar-ellenőrzéssel kezdődik. Eltérésnél **állj meg és kérdezz**.
- Commit üzenet vége: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Ág: `phase2d-hud`.

## Jarból ellenőrzött API-k (26.3)

- `CustomPacketPayload` (`type()`), `CustomPacketPayload.Type<T>` (rekord, konstruktor `Type(Identifier)`).
- `PayloadTypeRegistry.playS2C().register(Type<T>, StreamCodec<? super B, T>)` (a `PayloadTypeRegistry` a `net.fabricmc.fabric.api.networking.v1` csomagban).
- `ServerPlayNetworking.send(ServerPlayer, CustomPacketPayload)`.
- `ClientPlayNetworking.registerGlobalReceiver(Type<T>, PlayPayloadHandler<T>)`; a kezelő `receive(T payload, ClientPlayNetworking.Context context)`. A `context` tagjait (pl. a kliens elérése) a megvalósításkor jarból ellenőrizd.
- `StreamCodec.of(StreamEncoder, StreamDecoder)`, `ByteBufCodecs.VAR_INT`, `BYTE`, `BOOL` (mind `StreamCodec<ByteBuf, ...>`).
- `HudElementRegistry.addLast(Identifier, HudElement)`; `HudElement#extractRenderState(GuiGraphicsExtractor, DeltaTracker)` (**nem** `render`!).
- `GuiGraphicsExtractor#fill(int x1, int y1, int x2, int y2, int argb)`, `#text(Font, Component, int x, int y, int color)`.
- `Minecraft.getInstance()`, `.level` (`ClientLevel`), `.font`; a `ClientLevel#getGameTime()` és `#dimension()` örökölt.
- A `ServerEntityWorldChangeEvents` **nincs** az entity-events API-ban: a belépést és dimenzióváltást a `ShipStatusSyncPolicy` "újonnan a hajóban" logikája kezeli, nem esemény.

## Review Focus

- A kliens érvénytelen sorszámú (hibás vagy régi) csomagot kap: a dekódolás nem dob kivételt, az érvénytelen incidens kimarad, az érvénytelen fázis `LANDED`. Teszt: Task 1.
- A panel nem látszik a hajón kívül, és kilépés után eltűnik. Kézi: Task 5.
- Belépés vagy dimenzióváltás után a játékos azonnal megkapja az állapotot (nem vár a következő másodpercre). Teszt: Task 3 (`ShipStatusSyncPolicy`), kézi: Task 5.
- A hátralévő idő nem megy negatívba, és a két csomag közti visszaszámlálás nem ugrál. Teszt: Task 2.
- Dedikált szerver nem tölt be kliens osztályt. Kézi: Task 5 (`runServer`).

**Interfaces:**

- Produces:
  - `ShipStatusSyncPolicy.decide(Set<UUID> inShip, Set<UUID> known, boolean changed, boolean periodic) -> Result`; `record Result(Set<UUID> sendTo, Set<UUID> nextKnown)`: `changed` vagy `periodic` esetén mindenkinek a hajóban; különben csak az `inShip − known` (újonnan belépők); `nextKnown` = `inShip` (aki kilép, kikerül, hogy visszatérve újra kapjon azonnal).
